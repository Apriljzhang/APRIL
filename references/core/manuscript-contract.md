# APRIL manuscript contract

Use this compact record to preserve consequential decisions across APRIL stages. It is shared state, not permission to run the full pipeline.

## Record when known

| Field | Record |
|---|---|
| Requested task | Operation, object, deliverables, exclusions, stopping point |
| Publication target | Journal, article type, audience, author instructions, word limits |
| Research problem | Concrete problem or unresolved scholarly issue |
| Optional empirical narrative | Record only when narrative development is requested or material: phenomenon/puzzle; tested or proposed explanation; tested or proposed conditions; bounded answer/contribution |
| Purpose and contribution | What the study examines and what it may add |
| Questions and hypotheses | Exact wording; primary, secondary, or exploratory status |
| Key concepts | Canonical terms, definitions, distinctions, and forbidden conflations |
| Design and claim type | Design, unit of analysis, time order, descriptive/associational/causal/predictive claim boundary |
| Data and sample | Population, setting, sampling, sources, exclusions, missingness, relevant groups |
| Analysis | Primary method/estimand or qualitative objective, support procedures, planned robustness |
| Evidence status | Verified, inferred, proposed, missing, or disputed |
| Main findings | Locked results or themes and their evidence boundaries |
| Style and format | Language variety, journal style, file format, tables/figures |
| Open decisions | Decision owner, alternatives, dependencies, and what would resolve them |

## Rules

- Preserve the user's wording for locked RQs, hypotheses, construct labels, theme names, quotations, and group names.
- Distinguish a decision from a provisional recommendation and a verified fact from an inference.
- Surface contradictions between a new instruction and the existing contract instead of silently choosing one.
- Update only fields affected by the current task. Do not fill unknown fields by guessing.
- Keep the record in the conversation or working notes by default. Persist it as a file when the user requests one or when an authorised continuing workflow needs durable cross-stage state; mention the file rather than treating it as an additional manuscript deliverable.
- A handoff carries the relevant contract fields to the next stage; it does not authorise that stage to run.
